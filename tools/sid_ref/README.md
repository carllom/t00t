# Chip module reference rig (F0)

Ground-truth comparison harness for the chip (SID) module. See [chip.md](../../chip.md)
§11 for why it exists and §1 for how it gates the phases.

The short version: this module's primitives are a chain of small, exact,
unglamorous curves — a 23-bit shift register, a rate-counter envelope with
piecewise-exponential segments, two R-2R ladders, a nonlinear cutoff mapping.
When the composite output is wrong, ears cannot tell you which one it is. So the
loop runs through numbers instead: render the same register stream through reSID
and through t00t, diff what is exactly diffable, score the rest.

That ordering is deliberate, and it is the FM module's lesson taken up front
rather than after the fact ([fm2.md](../../fm2.md) §1): its calibration pass was
scheduled last, every phase before it was validated by ear, and the result was
six compensating constants that existed only to cancel each other out.

## Setup

```bash
cd tools/sid_ref
./fetch_resid.sh            # reSID's SID core, pinned commit -> resid/
make                        # -> ./resid_render ./resid_dump ./resid_probe

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# t00t side
make -C ../host_render -f Makefile.chip
```

`resid/`, `.venv/` and `out/` are gitignored — nothing third-party is vendored
into this repo, and `fetch_resid.sh` pins what it downloads. reSID is GPL-2;
nothing here is ever linked into the device firmware. This is host-only tooling.

## Use

Both renderers take the identical CLI, deliberately, so the compare script is a
thin diff rather than a translation layer:

```bash
./resid_render                --stream streams/saw_c3.sidreg --out out/ref.wav
../host_render/render_sid     --stream streams/saw_c3.sidreg --out out/test.wav
.venv/bin/python ../sid_compare.py out/ref.wav out/test.wav
```

The whole corpus, which is what the phase gates actually use:

```bash
.venv/bin/python ../sid_compare.py --all --json out/scorecard.json
```

### Control-plane conformance

No audio, no spectra — just numbers, compared exactly. This is the half that
can fail loudly:

```bash
.venv/bin/python ../sid_ctl_diff.py
.venv/bin/python ../sid_ctl_diff.py --only lfsr --verbose
```

`tools/sid_ref/resid_dump.cpp`'s header comment is the authority on what each
domain's columns mean. Change a domain and you must change both sides together.

### Regenerating the filter tables

`src/chip/sid_tables.h` is generated and committed. It only needs regenerating
when `fetch_resid.sh`'s pinned SHA moves or `sid_filter.h`'s recurrence changes:

```bash
./resid_probe --mode fc  --fc-step 16 --res 0 --fmode lp \
    --out out/probe_fc_lp.f32  --meta out/probe_fc_lp.json
./resid_probe --mode res --fc 1024 --fmode lp \
    --out out/probe_res_lp.f32 --meta out/probe_res_lp.json
cd ../.. && tools/sid_ref/.venv/bin/python tools/fit_6581_filter.py --refit
```

The fit takes about five minutes; without `--refit` it reuses
`out/fit_cache.json` and only re-emits the header.

Add `--pcm16 PATH` to either renderer for a peak-normalised listenable file.
Never analyse those — the per-file normalisation destroys the level information
`sid_compare.py` reports as its own metric.

## The register stream format

A stream is a text file of timed writes to `$D400–$D418`; `sidreg.h` is the
parser and both renderers share it verbatim, so the two can only disagree about
what a write *sounds* like, never about when it lands.

```
model 6581
clock pal
frames 200

@0 18 0f          # $D418 = $0f  (volume 15)
@0 04 21          # $D404 = $21  (sawtooth + gate)
@100 04 20        # gate off at frame 100
```

Writes land on frame boundaries only. That is a statement about what this module
*is* rather than a limitation: chip.md §6.2 makes the frame the chip's control
clock, and it is also the only timebase a cycle-accurate reference and a
44.1 kHz engine can both honour exactly.

`streams/` is generated by `make_streams.py` and committed. Each stream isolates
one primitive or one interaction, so a scorecard row points at a piece of DSP
rather than at "the sound".

## What the metrics mean

| Metric | Reads as |
|---|---|
| `level gap` | absolute loudness difference. Reported alone, never folded into the shape metrics — a wrong output gain and a wrong filter are different bugs. |
| `band MAE` / `p95` | per-third-octave spectral error over frames where **both** engines are sounding. Third-octave rather than harmonic tracking because this corpus sweeps pitch, sweeps cutoff and includes noise. |
| `attack MAE` | the same, restricted to the first 100 ms. The timbre number that stays valid when `coactive_frac` is low. |
| `centroid ratio` | brightness. `1.0x` is a match; `<1` reads as "too dull", `>1` as "too bright". |
| `envelope MAE` | the timing axis — "delayed envelope", "weak sustain". |
| `coactive_frac` | how much of the reference's sounding time the spectral numbers cover. A low value is itself an envelope finding. |

## Files

| | |
|---|---|
| `fetch_resid.sh` | reSID's SID core at a pinned SHA, plus the `siddefs.h` autoconf would generate. Bump deliberately: it moves every baseline number. |
| `sidreg.h` | the register-stream parser, shared by both renderers. |
| `resid_render.cpp` | the reference renderer. |
| `resid_dump.cpp` | control-plane ground truth as CSV: envelope, noise, waveform logic, DAC tables. The authority on those domains. Reference side only — t00t derives its DAC tables independently, so that diff is a real test. |
| `resid_probe.cpp` | records reSID's filter response over the cutoff and resonance grids, for the fit. |
| `make_streams.py` | generates `streams/`. |
| `baseline_f0.json` | the committed F0 scorecard — what every later phase is measured against. |
| `../fit_6581_filter.py` | fits `src/chip/sid_tables.h` to the probe recordings, and derives the R-2R DAC tables from the ladder's resistor ratio. |
| `../sid_ctl_diff.py` | the exact control-plane suite. |
| `../sid_compare.py` | the spectral scorecard. |
| `../host_render/render_sid.cpp` | the t00t side, same CLI, plus its own self-check suite. |
| `../host_render/t00t_chip_dump.cpp` | the t00t side of the control-plane dump. |
